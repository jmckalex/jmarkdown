Tables and alerts

This page covers two block constructs that share a common visual purpose — presenting information in a structured, scannable form. Tables arrange data in rows and columns; alerts set a passage apart in a coloured callout box. Both go beyond plain GitHub-Flavored Markdown, and both render to HTML for the web and to LaTeX for print from a single source.

JMarkdown's tables are an extended dialect that adds column spanning, row spanning, per-column alignment and width, and two headerless forms — all on top of ordinary GFM table syntax, so existing tables keep working unchanged. Alerts are callouts in Obsidian's style — > [!NOTE], > [!warning] A title, > [!tip]- Folded — covering every Obsidian type (GitHub's five alerts among them) plus JMarkdown's own suggestion, with icons, custom titles, folding and custom types.

Throughout, the live demos show the source on the left and its rendered result on the right, so the examples can never drift from what the parser actually does.

Tables

A JMarkdown table is a block of pipe-delimited lines. The familiar GFM form is a header row, a separator row, and zero or more body rows:

Markdown code
Markdown output
| Letter | Number |
|--------|-------:|
| A      |      1 |
| B      |     22 |
| C      |    333 |
Letter Number
A 1
B 22
C 333

The cells of every row are separated by the pipe character |. A leading and a trailing pipe are conventional and recommended; the separator row (the dashes) both marks where the header ends and — as we will see — carries the alignment and width information for each column.

Inline markdown is processed inside every cell, so emphasis, code spans, links, and inline math all work:

Markdown code
Markdown output
| Construct | Example         |
|-----------|-----------------|
| *Emphasis*  | /slanted/ text |
| `Code span` | `f(x)`         |
| Math        | $e^{i\pi}+1=0$ |
Construct Example
Emphasis slanted text
Code span f(x)
Math $e^{i\pi}+1=0$

Alignment

Put a colon at one or both ends of a column's dashes in the separator row to set that column's horizontal alignment:

Separator Alignment
:--- left
:---: centre
---: right
--- default (browser left)
Markdown code
Markdown output
| Left   | Centre | Right |
|:-------|:------:|------:|
| a      | b      | c     |
| longer | longer | longer |
Left Centre Right
a b c
longer longer longer

Alignment is emitted as an inline text-align style on each affected cell, and on the LaTeX path it selects the l, c, or r column specifier in the generated tabular.

Column widths

A column's width can be set directly in the separator row by embedding a percentage between the dashes — ---30%---. The width is applied as a CSS width on every cell in that column (and on the LaTeX path it becomes a fixed-width paragraph column, p{0.30\textwidth}):

Markdown code
Markdown output
| Term | Definition                         |
|------|--------------60%-------------------|
| API  | A contract between two programs.   |
| CSS  | A language for styling documents.  |
Term Definition
API A contract between two programs.
CSS A language for styling documents.

The percentage must be a whole number from 1 to 100. Width and alignment can be combined in the same column — :---30%---: is a centred 30

Column spanning

To make a cell span several columns, end it with extra trailing pipes — one pipe per additional column. A cell that should occupy three columns is closed with three pipes (|||): the cell itself, plus two for the columns it absorbs.

Markdown code
Markdown output
| H1      | H2      | H3      |
|---------|---------|---------|
| This cell spans all three columns |||
| Two columns             || One |
H1 H2 H3
This cell spans all three columns
Two columns One

The colspan count is exactly the number of consecutive pipes that close the cell. The remaining cells on that row fill the columns that are left.

Row spanning

To make a cell span downward into the row below, place a caret ^ at the end of the cell in the lower row, in the column you want merged upward. The lower cell's text (everything before the ^) is appended to the cell above, and the two are rendered as a single cell with a rowspan.

Column spanning and row spanning compose. In the table below the top-left cell spans two columns and two rows at once — two trailing pipes give it the colspan, and the ^ on the row beneath gives it the rowspan:

Markdown code
Markdown output
| This header spans two       || Header A |
| columns and two rows       ^|| Header B |
|-------------|-----------:|----------|
| Cell A      | Cell B     | Cell C   |
This header spans two columns and two rows Header A
Header B
Cell A Cell B Cell C

For a ^ to merge a cell upward, the cell above it must have the same colspan and start in the same column; otherwise the caret is treated as ordinary text.

Headerless tables

Not every table wants a header row. JMarkdown recognises two headerless forms.

Separator-first

If the first line of the block is a separator row, the table has no header but still gets per-column alignment and width from that separator. The rows beneath are all body rows:

Markdown code
Markdown output
|:------|:-----:|------:|
| Left  | Centre | Right |
| a     | b      | c     |
Left Centre Right
a b c

Pure pipe-delimited

If you want neither a header nor a separator, simply write pipe-delimited lines. Every line must begin and end with a pipe (apart from surrounding whitespace), and the column count is taken from the first row:

Markdown code
Markdown output
| Apples  | 12 |
| Bananas |  8 |
| Cherries | 30 |
Apples 12
Bananas 8
Cherries 30

A pure pipe-delimited table has no separator row, so it cannot carry alignment or width — for those, use the separator-first form. Colspan (||) and rowspan (^) still work in both headerless forms.

Escaping pipes

Because | separates cells, a literal pipe inside a cell must be escaped with a backslash, \|:

Markdown code
Markdown output
| Operator | Meaning          |
|----------|------------------|
| `a \| b` | bitwise or       |
| `a \|\| b` | logical or     |
Operator Meaning
a | b bitwise or
a || b logical or

Tables in LaTeX

On the LaTeX path each table is emitted as a tabular environment, ruled with booktabs — \toprule at the top, \midrule under the header, \bottomrule at the foot, the publication style rather than \hline (the package is pulled in automatically). Alignment maps to the l c r column specifiers, a percentage width becomes a fixed-width paragraph column (p{0.30\textwidth}), column spanning uses \multicolumn, and row spanning uses \multirow. Because of \multirow, any document that uses row spanning needs \usepackage{multirow} in its preamble.

A plain tabular cannot break across pages, so a long table would overflow a printed page. JMarkdown handles this automatically: a table longer than twenty body rows is emitted as a longtable instead (which still rules with booktabs and repeats its header on each page), so very long tables flow across pages with no change to your source.

Table syntax reference

Feature Syntax Notes
Header table header separator body rows standard GFM
Headerless (aligned) separator row first alignment + width, no header
Headerless (plain) pipe-delimited lines only no alignment or width
Left align :--- in separator row
Centre align :---: in separator row
Right align ---: in separator row
Column width ---NN%--- 1–100, in separator row
Column span trailing ` ` (one pipe / extra column)
Row span ^ at end of cell in lower row colspan + column must match
Literal pipe | inside a cell

Alerts

An alert — Obsidian calls it a callout, and it is also known as an admonition — is a blockquote tagged with a type marker on its first line. JMarkdown renders it the way Obsidian does: an accent-coloured left border, a light tint of the accent behind the text, and a title row with the type's icon. The marker is [!type] as the first line of a blockquote:

Markdown code
Markdown output
> [!NOTE]
> Highlights information that users should take into
> account, even when skimming.

Note

Highlights information that users should take into account, even when skimming.

The body of the alert is ordinary markdown, so it may span several lines and contain emphasis, lists, links, maths, code, and so on. Everything after the [!type] line becomes the box's content. The marker is matched without regard to case: [!NOTE], [!Note] and [!note] are the same.

The built-in types

GitHub's specification defines five alerts. JMarkdown accepts all five, each with its own colour and icon:

Markdown code
Markdown output
> [!TIP]
> Optional information to help a user be more successful.

Tip

Optional information to help a user be more successful.

Markdown code
Markdown output
> [!IMPORTANT]
> Crucial information necessary for users to succeed.

Tip

Crucial information necessary for users to succeed.

Markdown code
Markdown output
> [!WARNING]
> Critical content demanding immediate attention due to
> potential risks.

Warning

Critical content demanding immediate attention due to potential risks.

Markdown code
Markdown output
> [!CAUTION]
> Negative potential consequences of an action.

Warning

Negative potential consequences of an action.

In Obsidian's scheme, which JMarkdown follows, important is another name for tip and caution another name for warning, so each pair looks the same. Obsidian defines a dozen more types besides, several with aliases of their own; all are listed in the reference table at the end of this page. question is one of them, and suits the marginal commentary that arises when drafting:

Markdown code
Markdown output
> [!QUESTION]
> Is this assumption still warranted given the new data?

Question

Is this assumption still warranted given the new data?

JMarkdown adds one type of its own, suggestion, with a lightbulb:

Markdown code
Markdown output
> [!SUGGESTION]
> Consider splitting this section into two.

Suggestion

Consider splitting this section into two.

A type JMarkdown does not know is drawn as a note, titled with its own name — [!aside] becomes a note headed "Aside" — as Obsidian draws one.

Titles, folding and nesting

Text after the marker replaces the type's name as the title, and may contain markdown:

Markdown code
Markdown output
> [!warning] Mind the *gap*
> The title row keeps the type's icon and colour.

Mind the gap

The title row keeps the type's icon and colour.

A - straight after the marker makes the alert foldable, starting closed; a + makes it foldable, starting open. The title becomes a summary line with a chevron that opens and closes it — no script involved:

Markdown code
Markdown output
> [!tip]- Click to open
> Hidden until the title is clicked.
Click to open

Hidden until the title is clicked.

Alerts nest: inside an alert, a line starting > > begins another.

Markdown code
Markdown output
> [!note] The outer alert
> Some text.
>
> > [!example] An alert inside it
> > More text.

The outer alert

Some text.

An alert inside it

More text.

How an alert renders

An alert becomes a <div> carrying both Obsidian's names (callout, data-callout) and GitHub's (markdown-alert-<type>), so a stylesheet written for either applies. For > [!NOTE] the markup is: 

<div class="callout markdown-alert markdown-alert-note" data-callout="note">
  <p class="callout-title markdown-alert-title"><svg class="callout-icon">…</svg><span class="callout-title-inner">Note</span></p>
  <div class="callout-content">…the body…</div>
</div>

A foldable alert is a <details> element instead, its title a <summary>. An alias renders as its type: [!caution] gives data-callout="warning".

Icons and styling

The icons are Font Awesome's, written into the page as inline SVG, so they show with no icon font loaded and print as they look. The colours, border, tint and spacing come from the standard stylesheet (jmarkdown.css), keyed on data-callout. To restyle a type, target it in your own stylesheet — .callout[data-callout='note'] { --callout: teal; } recolours the note's border, icon, title and tint at once.

In print, each alert becomes a box drawn to the same design, with the same icon: see Print rendering.

Custom types

New types — or a new title, icon or colour for a built-in one — are defined in the project's .jmarkdown/config.json (or the global ~/.jmarkdown/config.json) under Callouts:

{
	"Callouts": [
		{ "name": "recipe", "title": "Recipe", "icon": "utensils",
		  "color": "rebeccapurple", "aliases": ["cook"] },
		{ "name": "warning", "color": "#c2410c" }
	]
}
  • name — the [!name] it answers to: a letter, then letters, digits, - or _. A built-in's name changes that type.
  • title — the default title (otherwise the name, capitalised).
  • icon — a Font Awesome Free icon by name: lightbulb, or with its family, regular:circle or brands:github.
  • color — a CSS colour: hex, rgb(), hsl() or a colour name. A colour too pale to read on the page is darkened until it does.
  • aliases — further [!alias] spellings for the type.

Every definition is checked. One that is malformed — a name that is not a name, an icon that does not exist, a colour that is not a colour — is skipped with a warning naming the entry and the reason, and never half-applied.
